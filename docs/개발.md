```

                 · dex(도감 · 기록 · 창) · manual(매뉴얼) · cloud(☁️ 구글 로그인 · 드라이브) · main(오늘의 정원 · 그리기 반복 · 시작). index.html이 이 순서로 부름
```

## 로컬에서

Node.js 24 이상 (빌드 도구 · 패키지 없음).

```bash
node flower-land/serve.js
```

(포트를 바꾸려면 `node flower-land/serve.js flower-land 5180`)

→ http://localhost:5173 . **localhost에서만** ⚙️ 설정에 개발용 ⏩ 시간 묶음(배속 · 다음 달 건너뛰기)이 보여요.

```bash
node flower-land/tests/run.js
```

엔진 테스트 51개 파일 (🌸 season.test.js 새 철 · 📮 mail.test.js 운영자 편지 — 실제 `mail.json` 검사 · 🎁 starterpack.test.js 첫 방문 꾸러미 · 첫 손님 · 🧺 store.test.js 정원 저장고 · 📊 economy.test.js 꽃별 셈 · 🧺 careall.test.js 모두 물 주기 · 모두 거두기 · auto.test.js 자동 장치 · ☁️ 드라이브: cloud.test.js 판단 · drive.test.js 통신 · cloudreward.test.js 로그인 보상 · 🎁 returngift.test.js 선물 답례품 · 🗑️ fullreset.test.js 완전 초기화 · freshgarden.test.js 거의 새 정원 · 🌸 guidepot.test.js 첫걸음 화분 단계 · 📈 yearlog.test.js 해마다 기록 · 🐢 slow.test.js 느긋하게 보기 · 🌱 grade.test.js 정원 등급 · gradeview.test.js 등급 화면 · 📈 graph.test.js 해마다 그래프 · 🗓️ weekly.test.js 주간 목표). 배포 워크플로도 이걸 먼저 돌리고, 실패하면 배포하지 않아요.

**🌱 정원 등급 (P28-05-01)**: 정원에서 한 일에 경험치를 주려면 `E.addXp(st, 종류, n, ctx)` (종류는 `E.XP` — 새로 생기면 표에 더하고 시뮬 주마다 등급 표를 다시 봐요). 돈을 주고 사는 것에는 주지 않아요(P17-14). 오르면 `ctx.onGrade` 이벤트(화면은 `E.gradeAlerts`로 알림), 읽기는 `E.gradeOf(st)` · 화면은 `E.gradeView` (도감 등급 쪽) · `E.gradeBadge` (위 막대).

**🐢 느긋하게 보기 (P28-02)**: 새 숫자 · 목표 화면(정원 등급 · 그래프 · 주간 목표 · 효율 표 …)을 만들면 `E.slowView(st)`가 참일 때 숨겨요. 숨길지는 이 함수 하나만 보고, 얻는 규칙은 바꾸지 않아요. 📈 해마다 그래프는 숫자 · 견줌만 빼고 모양은 남겨요(P28-07-02).

**🗓️ 주간 목표 (P28-09)**: 목표 종류는 엔진 `WEEKLY` 표(쉬움 · 보통 · 어려움 · `ev` 어떤 일에 오르는지 · `fam` 같은 주에 한 줄 · `open` 그 정원이 연 기능인지). 새 행동이 목표에 들어가야 하면 그 엔진 함수에서 `E.weekNote(st, ev, info, n, ctx)`를 부르고 표에 한 줄 더해요. 돈을 내고 끝나는 일은 목표로 넣지 않아요(P17-14). 화면은 `weeklyView` · `weeklyAwayLine`만 읽고, 느긋하게 보기면 null이에요. DEV ⏩ 시간 묶음에 "🗓️ 하나 끝 · 다음 주".

**🧺 자동 장치 (P28-10)**: `DECOS[k].auto` 3가지(자동 수확 바구니 · 자동 건조대 · 찻집 일손, `need` = 열리는 정원 등급). 바구니 · 건조대는 `onSlot`에서 꽃잠이 아닌 달이 끝날 때(`basketTick` → `rackTick`), 일손은 `advance` 걸음마다 팔기 바로 앞(`helperTick`). 손으로 할 때보다 더 벌지 않게(P17-14) 맞췄으니 값을 바꾸면 `auto.test.js`의 "더 벌지 않음"과 시뮬 `--auto`를 다시 봐요. "자리를 비운 동안"은 `autoStats` · `autoAwayLines`로 장치마다 한 줄.

**💧 한꺼번에 돌보기 (P28-11)**: "모두 물 주기 · 모두 거두기"는 엔진 `careAll(st, kind, ctx)` — `canCare`로 고른 꽃을 용품 수만큼 잘라 `care`에 한 번에 넘겨요. 그래서 돌보기 · 수확 규칙(경험치 · 주간 목표 · 도감)을 바꿀 땐 `care`만 고치면 둘 다 따라가요. 화면은 `careAllBtns`(정원 위 칩 줄 · 자리를 비운 동안 창, 두 포기부터).

**🧺 정원 저장고 (P28-04)**: `advance`가 흐르는 달에만 `pantryTick`을 불러 2시간마다 `PANTRY_CYCLE` 차례로 한 칸, 상한은 `PANTRY_CAPS`(정원 등급 표). 받기는 `takePantry`, 화면은 `pantryView`만 읽어요(느긋하게 보기면 숫자만 null). 쌓이는 것을 바꾸면 `pantryDayValue()`가 하루 용돈(`DAILY_GIFT`) 아래인지(`store.test.js`)와 시뮬 `--pantry`를 다시 봐요 — 떨어진 꽃잎은 바구니 1번을 써서 사람이 거두는 값과 같게 했어요.

**🌟 등급 보너스 (P28-05-02)**: 점은 `bonusPoints`(정원 등급 5마다 1점)만, 고르기는 `bonusSet(st, key, level)`(점이 모자라면 거부 · 내리면 점이 돌아옴), 화면은 `bonusView`만 읽어요(느긋하게 보기 숨김은 화면이 `E.slowView`로). 표 `BONUS[칸].vals[단계]`가 규칙이 읽는 값이고, 읽는 곳은 `basketFlowers`(바구니) · `rackN`(건조대) · `pantryCap`(저장고) · `catchUpH`(따라잡기)뿐 — 새 칸을 더할 땐 수입(값 · 품질 · 꽃 수)이 늘지 않는지 `sim-economy.js --bonus=칸`으로 먼저 봐요(💧 물 오래는 여기서 걸려 뺌). 저장 `st.bonus = { 칸: 단계 }`. 화면(M3-2)은 📔 도감일지 `bonusHTML` · 📖 기록 카드 `bonusRecHTML` · 새 점 알림 `gradeToasts`, 끝까지 올린 장치 그림은 `decos.js`의 `_max` 도트를 `app.js` `decoArt`가 고름(새 그림을 더하면 `DECO_MAXED`에 한 줄).

**🌸 새 철 (P28-08)**: 조건은 `seasonReady`(이번 철 해마다 기록 3줄 + 꽃 13종) · `seasonCanStart`(꽃잠에만), 시작은 `seasonStart(st, ctx)`(화면은 `ctx.rng`를 꼭 넘겨요 — 안 넘기면 땅 600칸 뽑기가 `Math.random`이 돼요) — 정원을 제자리에서 새로 만들고 이어지는 칸 `SEASON_KEEP`만 옮겨요(🧺 자동 장치는 제자리, 다른 장식은 창고로). 저장에 칸을 더하면 새 철에 이어질지 비울지 정해 `SEASON_KEEP`에 넣거나 빼고 `season.test.js`에 확인을 더해요. 화면은 `seasonHint`(꽃잠 기록 끝 한 줄) · `seasonBadge`(위 막대)만 읽고, 해마다 기록 줄 · 한 해 기록 카드에 `season`이 있어요. 드라이브 고르기는 `cloudDecide`의 `seasons` · `first`.

**📊 꽃별 셈 (P28-06)**: 도감 표는 엔진 `flowerEconomy(by)`만 읽어요(정렬 `income` · `price` · `mature`). 값은 `FLOWERS` · `teaItemValue` · `classify` · `HARVEST_PETALS`에서 셈하니 꽃 값을 바꾸면 표도 따라 바뀌어요 — 숫자를 따로 적지 않아요. `economy.test.js`가 꽃마다 한 해를 돌려 거둔 꽃잎이 표와 같은지 봐요.

**📈 해마다 그래프 (P28-07-02)**: 화면은 엔진 `graphYears` · `graphAxis` · `yearDiffOf` · `yearPace`만 읽어요. 지난해 같은 때 견줌은 `st.yearPace`(달마다 쌓인 수입 · 경험치)로 셈해요.

```bash
node flower-land/tools/sim-economy.js 4 7
```

부지런한 정원사로 4년(씨앗 7) 경제 시뮬레이션. 같은 씨앗이면 결과가 같아요. "주마다 정원 등급" 표는 주(= 한 해)마다 끝 등급 · 경험치가 어디서 왔는지(P28-05-01), 맨 끝 "해마다 기록" 표는 정원에 쌓인 `yearLogOf` 줄(P28-07-01)이에요. `--no-grade-deco`는 등급 장식만 사지 않는 정원사, `--pantry`는 🧺 정원 저장고를 2시간마다 거두는 정원사(기본 정원사는 거두지 않음), `--auto`는 🧺 자동 장치를 사서 맡기는 정원사(`--no-spend --auto`면 장치만 삼 — 기본 정원사는 장치를 사지 않음), `--bonus`는 🌟 등급 보너스(P28-05-02) 4칸을 처음부터 끝까지 켠 정원사(`--bonus=rack,basket`처럼 몇 칸만도 됨 — 바구니 · 건조대 · 저장고 칸은 `--auto` · `--pantry`와 함께 써야 일함), `--season`은 해 수만큼 돈 뒤 그 해 꽃잠에 🌸 새 철(P28-08)을 시작해 다시 해 수만큼 도는 정원사(2철 해는 "2철 1"처럼, 끝에 1철 · 2철 해마다 연말 돈 · 찻집 수입 · 쓴 돈 견줌 — 시뮬 정원사는 꽃 13종을 다 못 피워 시작 직전 꽃 도감만 채움). 시뮬 정원사는 첫 안내를 마친 정원(`onboarded`)이라 🗓️ 주간 목표가 뽑히고, 끝에 "주마다 목표" 표가 있어요(정원사는 목표를 따로 쫓지 않음). 광산 판 · 손님 주문 · 기념품은 정원 이름표(gardenId)로 정해져서, 시뮬레이션 · 테스트에서 이것들을 쓰면 `st.gardenId`를 고정해요.

## 배포

`main`에 push하면 [Pages 워크플로](../.github/workflows/pages.yml)가 테스트 → `tools/build-site.js`로 화면 파일만 `_site/`에 모아 → Pages에 올려요 (1분 안팎).

- 화면에 새 파일을 추가하면 `tools/build-site.js`의 `FILES` 목록에도 넣어야 해요 (index.html이 부르는 파일이 빠지면 모으기가 실패해요).
- 배포본을 로컬에서 미리 보기:

  ```bash
  node flower-land/tools/build-site.js && node flower-land/serve.js _site
  ```

- 링크 미리보기 이미지를 다시 만들기:

  ```bash
  node flower-land/tools/make-og.js
  ```

  카카오톡은 미리보기를 기억하니, 바꾼 뒤엔 [카카오 공유 디버거](https://developers.kakao.com/tool/debugger/sharing)에서 캐시를 초기화해요.
- **주소를 바꾸지 마세요.** 진행(localStorage)과 구글 로그인 허용 주소(승인된 JavaScript 원본)가 이 주소에 묶여 있어요.

## 📮 편지 보내는 법 (P29 운영자 편지)

`flower-land/mail.json`에 편지를 적어 main에 올리면, 배포 뒤 게임을 연 플레이어의 받은 편지함(📖 도감 › ✉️ 편지)에 📮 편지가 오고 **🎁 받기**를 누르면 선물이 들어가요. 서버는 없어요 — 게임이 같은 사이트의 이 파일을 열 때 · 다시 볼 때 읽기만 해요(개인정보처리방침 4번).

1. GitHub 웹에서 저장소 › `flower-land/mail.json` › ✏️(Edit this file)
2. 목록 `[ ]` 안에 편지 한 통 `{ … }`을 더해요 (여러 통이면 사이에 쉼표). 지난 편지는 지우지 말고 둬도 돼요 — 기간이 지나면 더 안 와요
3. **Commit changes…** → main에 바로 커밋
4. 저장소 › **Actions** › 방금 커밋의 Pages가 **초록 ✓**인지 확인. 빨강 ✗면 「엔진 테스트」 › `mail.test.js` 줄에 무엇이 틀렸는지 나와요 — 고쳐서 다시 커밋 (틀린 동안엔 배포되지 않아 플레이어에게 이상한 선물이 가지 않아요)
5. 1~2분 뒤 반영돼요. 이미 열어 둔 게임은 다른 탭에 갔다 돌아오거나 새로고침하면 받아요

| 칸 | 뜻 |
|---|---|
| `id` | 받았는지 세는 이름표. 영문 · 숫자 · `-` · `_` (40자까지). **한 번 쓰면 바꾸지 않아요** — 바꾸면 새 편지로 또 가요 |
| `from` · `title` · `text` | 보낸 사람(20자) · 제목(30자) · 글(400자). 해요체로 짧게 |
| `gifts` | 선물 목록 `[{ "cat": 종류, "key": 키, "n": 개수 }]`, 없으면 `[]` |
| `start` · `end` | 받을 수 있는 기간 `YYYY-MM-DD`, 한국 시간 하루 단위 (`start` 00:00 ~ `end` 23:59). 기간이 지나도 이미 편지함에 온 선물은 받을 수 있어요 |
| `to` | `all` 기간 안에 게임을 연 모두 · `new` 기간 안에 정원을 시작한 사람(정원 이름표의 만든 때) · `before:YYYY-MM-DD` 그날 전에 시작한 정원. 한 사람만 고르기는 못 해요 |

## 저장

- 진행은 브라우저 localStorage `flower-land-v3`에 자동 저장 (불러오기 직전 정원은 `flower-land-v3-undo`).
- ⚙️ 설정 › 💾 저장: `.json` 파일로 내보내기 · 불러오기 · 되돌리기. 형식은 `engine.js`의 `makeSave` / `parseSave` (`format: 1`, 해시로 깨짐 확인). 구글 드라이브 저장도 같은 형식을 써요.
- ☁️ 구글 드라이브 (P20-04 ~ 08): `flower-land/app-cloud.js` 맨 위 `GOOGLE_CLIENT_ID`에 Google Cloud 콘솔의 웹 클라이언트 ID를 넣으면 켜져요 (비어 있으면 ☁️ 화면이 모두 숨고 구글 스크립트도 안 불러요). 보안 비밀(secret)은 쓰지 않아요.
  - 클라이언트의 **승인된 JavaScript 원본**: `https://ff-1204.github.io` · `http://localhost:5173` (다른 포트로 확인하려면 그 주소도 더해요)
  - 드라이브 앱 전용 숨김 폴더에 `garden.json` · `garden.prev.json`, 요약(정원 이름표 · 저장한 때 · 계정 첫 방문 · 구름 정원사를 받은 때 `reward`)은 파일의 appProperties에. 이 기기 기록(이메일 · 마지막으로 맞춘 판 · 첫 방문 · reward)은 localStorage `flower-land-v3-cloud`, 토큰은 끝날 때까지(약 1시간)만 `flower-land-v3-cloud-token`에 (`E.cloudTokenUse`, 로그아웃 · 401 · 끝남 · 다른 계정이면 지움)
  - 로그인 보상 「구름 정원사」(P20-16): 드라이브와 맞춘 정원에 `E.giveCloudReward` — 연출은 계정마다 한 번(`reward`가 있으면 조용히). 덤 칭호 · 덤 장식은 `EXTRA_TITLE_KEYS` · `EXTRA_DECO_KEYS`라 칭호 수 · 꾸밈 도감 칸에 넣지 않음
  - 무엇을 쓸지(여러 기기)는 `E.cloudDecide`, 다른 정원인데 한쪽이 거의 새 정원이면 묻지 않음(`E.freshGarden` · `E.freshPick`), 저장 간격은 `E.cloudDue` (5분, 닫을 때 · 지금 저장은 바로)
