# 구글 로그인 일반 공개 안내 (P20-09-07)

지금은 구글 로그인이 "테스트" 상태라 테스트 사용자로 등록한 계정만 로그인돼요. 이 문서는 누구나 로그인할 수 있게 "프로덕션"으로 바꾸는 순서예요. 콘솔 작업은 운영자가 직접 해요.

2026-11-26에 구글 공식 문서를 읽고 적었어요. 화면 이름과 규칙은 바뀔 수 있으니 줄마다 붙인 링크를 한 번 더 확인하세요.

## 먼저 알 것

| 무엇 | 결과 | 확인 정도 |
|---|---|---|
| 범위 심사 | 필요 없어요. `drive.appdata` · `openid` · `email` · `profile`은 모두 민감하지 않은 범위라서 범위 심사, 시연 영상, 보안 평가가 없어요 | 공식 문서 ([드라이브 범위](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) · [심사 종류](https://support.google.com/cloud/answer/13464321)) |
| 브랜딩 확인 | 필요해요. 모든 앱이 거쳐야 동의 화면에 앱 이름과 로고가 나와요. 거치지 않으면 앱 도메인만 보여요 | 공식 문서 ([브랜딩 확인](https://developers.google.com/identity/protocols/oauth2/production-readiness/brand-verification)) |
| 걸리는 시간 | 자동 확인은 보통 몇 분, 사람이 보면 2 ~ 3 영업일. 통과한 뒤 7일 안에 게시해야 하고, 넘기면 다시 확인받아요 | 공식 문서 (같은 링크) |
| 테스트 상태의 불편 | 테스트 사용자만 로그인되고, 동의가 7일 뒤 풀려서 약 일주일마다 다시 동의해야 해요. 프로덕션이 되면 없어져요 | 공식 문서 ([대상 설정](https://support.google.com/cloud/answer/15549945)) + 토큰 방식이라 "다시 동의"로 나타난다는 것은 추정 |
| **github.io 주소** | **막힐 수 있어요.** 아래 "가장 큰 걸림돌"을 먼저 보세요 | 공식 문서 + 다른 사람들의 사례 |

## 가장 큰 걸림돌: github.io 주소

- 공식 문서는 홈페이지가 "내가 소유한 확인된 도메인"에 있어야 한다고 해요. 공유 도메인을 쓰는 곳이면 자기 도메인을 쓰라고 권해요. GitHub Pages를 콕 집어 된다, 안 된다고 적은 곳은 없어요. ([정책 준수](https://developers.google.com/identity/protocols/oauth2/production-readiness/policy-compliance))
- 다른 사람들의 최근 사례 두 건에서는 Search Console에서 소유 확인까지 했는데도 브랜딩 확인이 github.io에서 실패했어요. 두 건 모두 구글의 답은 없었어요.
  - 2026-10: 브랜딩 화면에 "Domain not found: <이름>.github.io"가 뜨고 앱 게시 단추가 꺼진 채였어요. ([글](https://discuss.google.dev/t/google-oauth-domain-not-found-for-verified-github-pages-domain/404025))
  - 2026-11: `<사용자>.github.io/<저장소>/` 꼴 사이트에서 홈페이지가 "등록된 소유자가 아니다"로 실패했어요. ([글](https://github.com/achimgrimm/badminton-results/issues/54))
- 그래서 길이 두 가지예요.

| 길 | 할 일 | 좋은 점 | 걸리는 점 |
|---|---|---|---|
| A. 지금 주소로 먼저 해 보기 | 아래 순서 1 ~ 4를 그대로 해 보고, 브랜딩 확인이 실패하면 B로 | 돈이 안 들고 주소가 그대로예요 | 실패할 가능성이 있어요 |
| B. 자체 도메인 쓰기 | 도메인을 사서 GitHub Pages에 연결 | 브랜딩 확인이 될 가능성이 높아요 | 도메인 값이 들어요. **주소가 바뀌면 플레이어의 정원(localStorage)이 새 주소로 따라오지 않아요** |

B로 가면 게임 주소가 바뀌니, 하기 전에 기획이 따로 필요해요(예전 주소에서 저장 파일 받기 안내, 승인된 JavaScript 원본 · 정책 문서 주소 · 공유 주소 `SHARE_URL` 바꾸기). `docs/개발.md` "배포"에 "주소를 바꾸지 마세요"라고 적어 둔 까닭이에요.

A가 실패했을 때 브랜딩 칸을 비워 둔 채로 게시할 수 있는지는 확인하지 못했어요. 위 첫 사례를 보면 브랜딩이 덜 되면 게시가 막히는 것으로 보여요.

## 순서 (길 A)

Google Cloud 콘솔 › **Google Auth Platform** 아래 화면이에요. ([화면 안내](https://support.google.com/cloud/answer/15549049))

1. **Search Console에서 사이트 소유 확인**
   - [Search Console](https://search.google.com/search-console)에서 속성 추가 › **URL 접두어** › `https://ff-1204.github.io/doris-garden/`
   - 확인 방법은 HTML 파일이나 메타 태그예요. 파일은 속성의 맨 위 경로에, 메타 태그는 속성의 첫 페이지에 넣어요. ([확인 방법](https://support.google.com/webmasters/answer/9008080))
   - 받은 파일이나 태그를 알려 주면 저장소에 넣는 일은 Claude가 할 수 있어요. 파일이면 `flower-land/`에 넣고 `tools/build-site.js`의 `FILES`에 더해요. 메타 태그면 `flower-land/index.html` 머리에 넣어요.
   - Cloud 프로젝트의 소유자나 편집자인 구글 계정으로 확인해야 해요.
2. **Branding 화면 채우기**
   - 앱 이름 "도리의 정원", 지원 이메일, 로고(1MB 이하 JPG · PNG · BMP, 120×120 권장)
   - 앱 도메인: 홈페이지 `https://ff-1204.github.io/doris-garden/` · 개인정보처리방침 `…/privacy.html` · 서비스 약관 `…/terms.html`
   - 승인된 도메인: `ff-1204.github.io`
   - 개발자 연락처 이메일
3. **Verify Branding** 누르기 → 결과가 "Ready to publish"면 **Publish branding**. "Need to fix issues"면 **View issues**로 까닭을 봐요. 여기서 github.io 문제가 나오면 길 B를 정해야 해요.
4. **Audience 화면** › **Publish app** → 게시 상태가 "In production"이 돼요.
5. **Verification Center**에서 Branding 상태와 Data access 상태를 확인해요.

## 홈페이지 · 개인정보처리방침 조건

공식 문서가 요구하는 것과 지금 상태예요. ([브랜딩 확인](https://developers.google.com/identity/protocols/oauth2/production-readiness/brand-verification))

| 조건 | 지금 |
|---|---|
| 홈페이지는 로그인 없이 열리고, 앱이 무엇인지 알려 주고, 기능을 설명해야 해요 (로그인만 있는 페이지는 안 돼요) | 게임이 바로 열리고 첫 안내 창이 떠요. 심사자가 설명으로 볼지는 확인하지 못했어요 |
| 홈페이지에 개인정보처리방침 링크가 있어야 하고, 동의 화면에 적은 주소와 같아야 해요 | 설정 › 정보에 정책 줄이 있어요. 첫 화면에서 바로 보이는 링크가 필요한지는 확인하지 못했어요 |
| 개인정보처리방침은 홈페이지와 같은 도메인에 있고, 구글 사용자 데이터를 어떻게 읽고 · 쓰고 · 저장하고 · 나누는지 적어야 해요 | `privacy.html`에 적혀 있어요 (P20-10-01) |

브랜딩 확인에서 홈페이지 쪽 지적이 나오면, 첫 화면에 게임 설명과 정책 링크를 더 잘 보이게 두는 고침을 Claude가 할 수 있어요.
