> 기획안이에요. 열린 질문은 10-28에 추천안으로 확정했고, P22-05가 끝나면 `체크리스트.md`에 P29 절로 옮기고 구현해요. 지금은 P22-05(첫 방문 꾸러미) 세션이 체크리스트와 받은 편지함 코드를 고치고 있어서 따로 적어 뒀어요. P22-05가 끝난 뒤 구현해요.

## 무엇
운영자가 저장소의 편지 파일 하나에 편지 내용과 선물을 적고 main에 커밋하면, 배포(GitHub Pages)된 뒤 게임을 연 플레이어의 받은 편지함에 편지가 와요. 플레이어가 **받기**를 누르면 선물이 들어와요. 서버는 없어요.

## 여정
- 운영자: GitHub 웹에서 `flower-land/mail.json`에 편지 한 통을 더해 커밋 → Actions 테스트(편지 파일 검사 포함) → 1~2분 뒤 배포
- 플레이어: 게임을 열면(또는 열어 둔 채 다시 볼 때) "✉️ 새 편지가 왔어요" → 받은 편지함에서 읽고 🎁 받기 → 창고 · 꿀 선반 · 광산 주머니에 들어옴
- 다른 기기(구글 드라이브로 이어 하기)에서 열어도 같은 편지를 두 번 받지 않음

## 세부 항목

- ⬜ **P29-01. 편지 파일 형식** — 추천: `flower-land/mail.json` (배포본에 같이 실림, `tools/build-site.js` `FILES`에 넣음)
  ```json
  [
    { "id": "2026-11-hello",
      "from": "꽃집 할머니",
      "title": "11월 인사",
      "text": "11월에도 정원을 찾아 줘서 고마워요.",
      "gifts": [ { "cat": "seed", "key": "rose", "n": 2 }, { "cat": "supply", "key": "water", "n": 3 } ],
      "start": "2026-11-01", "end": "2026-11-30",
      "to": "all" }
  ]
  ```
  - `id`: 한 번 쓰면 바꾸지 않음 (받았는지 셈하는 이름표)
  - `gifts`의 종류는 이웃 답례품(P26-06 `giveReturn`)과 같게: `seed` · `supply` · `honey` · `mine` · `deco`. 넣는 곳도 같음 (`RETURN_WHERE`). 처음 판에는 **돈 · 칭호는 넣지 않음** (돈 고리 · 칭호 19개 셈이 흔들림, 열린 질문 ②)
  - 날짜는 한국 시간 하루 단위 (`start` 00:00 ~ `end` 23:59). 게임 시간(현실 1주 = 1년)이 아닌 현실 날짜
- ⬜ **P29-02. 받는 사람(`to`)** — 추천 세 가지만
  - `all`: 기간 안에 게임을 연 모두
  - `new`: 기간 안에 정원을 시작한 사람만 (환영 편지용)
  - `before:YYYY-MM-DD`: 그 날 전에 시작한 정원만 (오래 한 사람 감사 · 사과 보상용)
  - 한 사람만 골라 보내기는 못 해요 (서버가 없고, 운영자는 플레이어를 모름 — 개인정보처리방침 3번)
- ⬜ **P29-03. 받는 흐름 (엔진)** — `mailDeliver(st, list, now)`: 기간 · 받는 사람이 맞고 아직 안 받은 편지를 `st.letterBox`에 넣고 `st.mailGot[id] = 받은 때`. `mailTake(st, id, ctx)`: 선물을 넣고 받음 표시. 편지만 온 채 받기를 안 눌러도 기간이 지나면 선물은 그대로 받을 수 있게(편지함에 있는 동안)
  - 저장: `st.mailGot`(MIGRATIONS 맨 끝 한 줄), 드라이브 · 파일 저장에 그대로 실려서 다른 기기에서도 두 번 안 받음
  - 받은 편지함이 가득(`LETTER_BOX_MAX` 60)이면 오래된 **받은** 편지부터 밀어냄, 선물을 안 받은 편지는 밀지 않음
- ⬜ **P29-04. 파일 읽기 (화면)** — 추천: 열 때 · 화면이 다시 보일 때(visibilitychange) `fetch('mail.json?v=<시각>', { cache: 'no-store' })`로 같은 사이트 파일만 읽음. 못 읽으면(오프라인) 조용히 넘어감
  - 개인정보: 같은 사이트의 파일을 **읽기만** 하고 아무것도 보내지 않음 → 방침 3번 그대로. 다만 방침의 "글꼴만 외부 접속" 문단 옆에 "새 편지가 있는지 이 사이트의 편지 파일을 읽어요" 한 줄을 더함 (열린 질문 ③)
- ⬜ **P29-05. 잘못 적은 편지 막기 (테스트 = 배포 문)** — `tests/mail.test.js`가 실제 `mail.json`을 읽어 검사: JSON 형식, `id` 겹침 없음, 날짜 형식 · `start ≤ end`, `gifts`의 `cat` · `key`가 엔진에 있음, `n`이 1~상한(열린 질문 ①), 문구 길이. 틀리면 Actions가 멈춰 **배포되지 않음** → 플레이어에게 이상한 선물이 가지 않음
- ⬜ **P29-06. 화면** — 받은 편지함에서 운영자 편지는 ✉️ 대신 📮(우체통) 표시, 선물 줄 + 🎁 받기 단추, 받으면 "창고에 넣었어요" 한 줄. 위 막대/알림 "📮 새 편지가 왔어요" (알림 설정 종류에 따름, 수면 시간이면 모았다가). 느긋하게 보기(P28-02)여도 편지는 보임 (숫자가 아니라서)
- ⬜ **P29-07. 운영자 안내** — `docs/개발.md`에 "편지 보내는 법" 절: GitHub 웹에서 파일 고치기 → 커밋 → Actions 초록 확인 → 1~2분 뒤 반영, 예시 편지 3가지(환영 · 계절 인사 · 점검 사과), 넣을 수 있는 선물 키 표
- ⬜ **P29-08. DEV 확인 단추** — localhost에서만 ⚙️ 설정 개발 묶음에 "📮 편지 파일 다시 읽기" · "받음 기록 지우기"

## 한계 (알고 가는 것)
- 싱글 게임이라 저장을 손대면 선물을 더 받을 수 있어요. 지금도 같아서 막지 않아요.
- 받은 기록은 정원 저장에 있어요. 파일로 예전 저장을 불러오면 그 사이 받은 편지를 한 번 더 받을 수 있어요 (드라이브로 이어 하는 경우는 안 생김).
